# Bakemono 实现状态

任务及验收以 [GitHub 总计划 #1](https://github.com/Monsterwi/bakemono/issues/1) 为准。本项目是单进程 HTTP 对象缓存代理；已有实现和测试不代表完成生产试用验收，也不代表与 ATS 磁盘格式兼容。

## 已实现

- **HTTP 主路径（#2–#5）**：标准库 HTTP 服务、回源 URL/头处理与取消、完整缓存身份、完整 GET 对象提交、连接/请求/回源/缓存写入限额、排空和基础运行计数。主程序和 demo 使用同一服务实现。
- **磁盘提交（#6）**：数据写入确认后发布目录，完整对象头最后提交；写入错误和截断对象中止；片段身份与覆盖代次防止混读；迁移队列有界。
- **校验与恢复（#7）**：正文和头部 CRC、对象/片段链/目录边界检查；只恢复经过完整验证的干净关闭检查点；运行会话标记阻止历史索引复活；恢复后当前及前一覆盖代次保持一致；同文件所有权及重叠区域检查。见 [存储格式与恢复](CACHE_STORAGE_FORMAT.md)。
- **生命周期与失效（#8）**：读写引用按持有者释放，Close/Abort 幂等，关闭读者可唤醒等待；回源前捕获失效代次，旧写者不能在 PURGE 后重新发布。完整键与 URL selector 映射持久化，支持跨条带的精确/前缀 PURGE。
- **共享缓存语义（#9）**：统一准入、Age/Date/freshness 与条件验证；支持 `s-maxage` 优先级、请求 `no-cache`/`max-age`/`min-fresh`，过期对象回源验证；304 仅更新经过条件检查的对象头，保留正文，源站 200 可替换对象。条件 GET/HEAD 使用对应表示的验证器，HEAD 复用完整 GET 元数据且不返回正文。
- **HTTP 变体（#9）**：隔离 `Vary: Accept-Encoding`、`Accept-Language` 及其组合；Vary 规则变化和 `Vary: *` 不复用旧表示。变体查找及 URL 失效在正常重启后仍有效。

- **TLS/H2 与健康检查（#10）**：证书和私钥成对配置，启动监听前加载；标准库 ALPN 支持 H2/H1，H2 多流仍受请求及回源额度控制。回源验证证书/主机名，可追加私有 CA。HEAD 健康检查有超时与连续失败/恢复阈值，停机取消并等待检查退出，空健康集及时返回失败。

## 管理与兼容边界

- HTTP PURGE 默认关闭。在 `records.config` 配置 `proxy.config.http.purge_token` 后，通过 `Authorization: Bearer <token>` 鉴权；先鉴权再失效。日志记录结果与数量，隐藏 PURGE 地址，配置打印隐藏 token。
- 无查询参数且路径以 `/` 结尾的 PURGE 按 selector 前缀失效；其余为精确失效。同 URL 的所有表示共享 selector。
- PURGE 采用保守代次：所有条带的在途读写都会失效，未匹配的已提交对象保留。当前只保证单进程内失效。
- 每个条带的映射受目录容量、65,536 条目、16 MiB 字符串总量及每键/selector 16 KiB 限制；满额时跳过缓存填充。HTTP 每个 URL 最多 16 个变体。
- HTTP 仍采用明确的共享缓存子集：Authorization/Cookie/Set-Cookie、其他 Vary 字段、未知或不支持的缓存指令组合保守旁路；不实现启发式 freshness 或全部 RFC 可选行为。
- 普通填充和 304 更新比较同一 selector 的快照，避免覆盖更新后的对象。不可缓存策略使用每条带 1,024 个哈希代次槽阻止旧回源发布，取消尚未提交的 writer，仅删除仍匹配原快照及原分配代次的已提交表示，保留快照之后的新提交；槽位碰撞可能额外跳过缓存填充，不会混用对象。
- 旧格式、损坏检查点或异常退出会冷启动，不删除或截断原缓存文件。正常环形写入仍会复用旧空间。缓存不承诺零丢失；不同进程不能共享同一文件，即使使用不重叠区域。

- 网络配置见 [records.config](../conf/records.config)。健康检查默认关闭；开启后每轮逐个源站发送 HEAD，最多一个额外探测请求，不计入业务请求额度。检查不跟随重定向，2xx/3xx 判健康；全源站检查耗时可能达到源站数乘单次超时。应用层自动重试未启用。
- 完整对象缓存的有序源站池沿用可互换副本假设。`proxy.Origin` 可固定一个源站的完整 URL 身份供多次请求使用，持有者必须保持所属 Proxy 存活，失败不会改选源站。

## 尚未实现或验收

- HTTP 请求合并回源（#12）尚未实现。HTTP 主路径只读取已提交完整对象；存储层内部 RWW 不等于安全共享回源。
- Range/206 部分缓存（#13）尚未实现。Range 请求透传回源；内部多片段存储不等于部分对象缓存。
- 动态配置（#11）以及真实负载下的容量、长期稳定性和回滚验收（#14）仍由后续任务完成。
- 不默认启用 stale-while-revalidate、stale-if-error 或共享身份请求缓存。

## 验证入口

`make test` 和 `make test-race` 均强制重新运行测试。测试使用临时缓存文件与本地源站，包含实际主程序 MISS→HIT、SIGTERM 排空、损坏数据及杀进程后的恢复、并发 PURGE 和读写生命周期、可控时钟、Vary/304/HEAD 与重验证竞争。`make build` 构建实际入口。

这些验证不覆盖物理断电、存储设备掉电保护或长期生产负载。
