# 第二轮热路径优化（2026-10-23）

测量源码 `77e5186`，对照 `e1b158a`；后续合并修复不冒充重测。当前 ATS 对照见 [新报告](ATS_COMPARISON_2026-10-24.md)。

| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 256 KiB / C100 QPS | 27,460 | 29,521 | +7.5% |
| C100 完整响应 P99 ms | 15.798 | 14.682 | −7.1% |
| C100 CPU μs/请求 | 297.6 | 277.4 | −6.8% |
| 固定 16k RPS 完整响应 P99 ms | 0.998 | 0.867 | −13.1% |
| 100 MiB / C8，MiB/s | 1,024.7 | 982.5 | **−4.1%** |
| 100 MiB / C32，MiB/s | 1,005.2 | 989.8 | **−1.5%** |

**改动**：RAM 复用解析元数据、请求内复用缓存策略、发送缓冲活动预算；保持 CRC/失效隔离。元数据打开分配 130→17 次，仅指该接口，不是整个 HTTP 请求。

**方法**：同机 HTTP/1.1、无 TLS、GOMAXPROCS=8。饱和组不绑核，前后版本交替各 3×10 秒；固定率组及大文件绑核，布局见 JSON。延迟含客户端计划发送排队；各轮指标取中位数，不混算不同组容量。

**验证**：固定率组每版本成功 1,680,000 次，零错误/丢弃；Otter HDD/SSD 和 S3-FIFO SSD 功能各 14/14，200 MiB、旧缓存恢复、normal/race/vet/工具通过。新任务 [#29](https://github.com/Monsterwi/razor/issues/29) 记录最终合并与 CI。

**代价**：C100 RSS 44.13→45.40 MiB；大文件吞吐回退。活动发送 payload 默认 64 MiB/runtime，空闲 sync.Pool 由 GC 管理，不是 RSS 硬上限。本轮未重跑 ATS 或两小时长测。
